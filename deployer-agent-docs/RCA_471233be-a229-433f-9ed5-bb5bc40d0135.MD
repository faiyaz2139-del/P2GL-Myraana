# RCA — Preview stuck on "Opening your shop… / Resuming…"

## Scope
Read-only diagnosis. No data, DNS, deployment, or settings were changed.

## Summary
The stuck "Opening your shop…" with the platform banner *"This is a static preview, your app is resuming and it may take 1-2 minutes"* is the **Emergent preview environment (agent-env pod) cold-starting from hibernation**. It is NOT a fault in the deployed production app, and it is unrelated to the custom-domain SSL issue.

## Evidence
- `describe_deployment_state`: deployment `p2g-production` is `active`; active run `471233be…` status `success`; template `fastapi_react_mongo_shadcn_base_image`; frontend_type `cloudflare`; tier_0.
- `preview_health_check /`  → **200**, serves SPA HTML (`main.1fc1c33b.js`).
- `preview_health_check /api/` → **200**, body `{"name":"Print2Go Production Studio","status":"ready"}` — backend up, API reachable.
- `list_domains`: `myraana.com` and `www.myraana.com` → `verified:false`, `ssl_status:pending_validation` (http method). This is the pre-existing, separate issue.

## Root cause
The preview pod hibernates when idle. On access it serves a **static cached snapshot of the frontend bundle** while the runtime resumes in the background. During that window the preview **backend is not yet accepting requests**, so any data-dependent screen (here, "Opening your shop…", which waits on an API/data fetch) hangs until the resume completes. Once the pod is fully up, the frontend's API calls succeed. This is expected preview-infrastructure behavior, not an application bug.

## "Are frontend API calls blocked after resume?"
- **In the deployed production app: NO.** `/api/` returns 200 and the backend reports `ready`. Frontend→backend API calls are working.
- **In the preview, DURING the static/resuming window: effectively yes, transiently** — the static snapshot loads but the preview backend isn't live yet, so the shop-load API call cannot complete until resume finishes. This clears on its own once the pod is up; it is not a routing/CORS/config block.

## What I could not inspect
I have no tool scoped to the preview/agent-env pod — I cannot wake it, read its logs, or force-resume it. Preview wake-up is platform-managed.

## Separate issue (unchanged, not acted on)
Custom domains `myraana.com` / `www.myraana.com` remain `pending_validation` (SSL cert via http validation), `verified:false`. Independent of the preview wake-up. No change made per instructions.

## Remediation
- Wait the stated 1–2 minutes for the preview to finish resuming, then reload. A hard refresh / incognito clears any stale static snapshot.
- If "Resuming…" persists well beyond a few minutes on repeated reloads, it is a platform preview-pod wake failure (agent-env), to be escalated to Emergent support — not a deployed-app or source fix.
